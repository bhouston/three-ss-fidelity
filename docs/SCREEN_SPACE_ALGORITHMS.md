# Screen-space algorithm reference and upstream change map

This is the implementation inventory for TRAA, SSR, SSGI, and AO in this repository. It connects the active algorithms to papers or original implementation sources, separates inherited behavior from our changes, and identifies the evidence needed for a three.js PR.

Reviewed October 1, 2026 against repository base `3201856bb06`, three.js fork `83c310af72715ae558beea12d169f00c62ea48eb`, and the `three-r186` npm alias (`three@0.186.1`). The experimental temporal profiles described below belong to [issue #111](https://github.com/bhouston/three-fidelity/issues/111). Uncommitted work in other worktrees is outside this inventory.

For the motivating noise problem and detailed literature discussion, see [GGX reflections and temporal reconstruction](SSR_TEMPORAL_RESEARCH.md). For the pipeline and historical results, see [THREE-NEW.md](THREE-NEW.md). Papers support particular algorithms and assumptions; they do not establish that every parameter we selected or every approximation we added is correct.

Upstream proposals must distinguish available implementations from the implementation actually selected by the adapter.

The AO output is **the visibility-bitmask AO attachment of SSGI**. `three-new` does not run a separate standalone GTAO or SSAO node. GTAO is part of its algorithmic ancestry; calling this implementation a complete GTAO implementation would be inaccurate.

## TRAA: sample accumulation and history validation

Relevant sources: [Karis 2014][K14], [Yang, Liu and Salvi 2020][Y20], [Playdead's temporal implementation][P], [Tardif's implementation article][T], and [López's implementation article][L]. The addon itself cites Tardif and López. Those sources are implementation guidance, not all peer-reviewed papers.

| Algorithm                           | Active implementation and choice                                                                                                                                                  | Difference from `three-current` / provenance                                                                                                                                                       |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Subpixel camera sampling            | A repeating 32-offset Halton(2,3) sequence jitters the projection                                                                                                                 | Inherited core TRAA behavior; [K14], [Y20], and addon implementation guidance                                                                                                                      |
| Jitter-free motion vectors          | Velocity uses the original projection; history UV is current UV minus converted NDC velocity                                                                                      | Inherited principle. `three-new` supplies velocity from its separate geometry pre-pass, so cross-pass consistency must be tested                                                                   |
| Depth-based velocity dilation       | Select closest depth in a 3x3 neighborhood and use that texel's velocity; also track farthest depth                                                                               | Inherited. Handles foreground edges; traversal/tie order matters when optimizing shader loops                                                                                                      |
| Previous-depth validation           | Reconstruct previous view/world position and compare its depth in the current camera frame; reject off-screen history                                                             | Inherited. Depth-edge logic can permit history at edges; it is a heuristic, not perfect visibility validation                                                                                      |
| History resampling                  | Bilinear sampling of the resolved history                                                                                                                                         | Inherited quality limitation: repeated interpolation can blur detail during motion. Catmull–Rom remains a candidate, not an implemented fix                                                        |
| Current sample reconstruction       | One sample of the jittered beauty texture                                                                                                                                         | Inherited. A wider reconstruction filter remains a candidate; static shimmer and thin-edge coverage require tests                                                                                  |
| Variance clipping                   | 3x3 RGB mean/variance, motion-dependent gamma; history clipped toward an AABB center                                                                                              | Inherited. [P] is the explicit source for the clip-to-center helper. This differs from SSR's componentwise YCoCg clamp                                                                             |
| Motion/subpixel weighting           | Ordinary mode starts at 5% current weight, adds motion response and optional subpixel correction                                                                                  | Inherited moving-view behavior. More current weight improves responsiveness but exposes stochastic noise; reducing it needs ghosting tests                                                         |
| HDR flicker reduction               | Compress colors for luminance-derived blend weights, normalize weighted current/history contributions                                                                             | Inherited helper. Relate to [K14] and inspect exact `TAAUtils` equations; do not assume the result is a plain arithmetic mean                                                                      |
| Still-view progressive accumulation | Once still for enough frames, valid zero-motion pixels bypass clipping/flicker weighting and blend using a decreasing `1/(n+1)` weight                                            | Fork addition enabled by `three-new`; empirical choice documented in [SSR temporal history](history/SSR_TEMPORAL.md). This is ordinary running-mean mathematics, not a new published TAA algorithm |
| Precision and reset                 | Progressive history uses float32; resize initializes fresh history. Camera stillness controls the counter; adapter resets accumulation when its scene-transform signature changes | Fork/pipeline choices. `resetAccumulation()` resets the progressive counter, not every history resource. Materials, lighting, cuts, and animated normals need explicit change handling             |
| Pass scheduling                     | Jitter applied before the rendering pipeline and cleared afterward                                                                                                                | Fork scheduling differs from stock synchronization details. This is an implementation invariant, not established by a successful static screenshot                                                 |
| Shader-size optimization            | Local vendored variant replaces generated unrolled neighborhoods with TSL loops and explicit expression reuse                                                                     | Local implementation work described in [shader audit](history/SHADER_CODE_SIZE.md); verify active imports before attributing it to the selected pipeline                                           |

For upstream PRs, separate a reconstruction-quality proposal from progressive still-view averaging, precision changes, and scheduling fixes. Their acceptance criteria differ. [TRAA diagnostic history](history/TRAA_TESTS.md) covers checker convergence, motion recovery, disocclusion, and still flicker; continuous-motion reference comparisons are still needed.

## SSR: GGX sampling, tracing, shading, and reconstruction

### Estimator and tracing

| Algorithm                       | Source / theoretical relation                                                                                                 | `three-new` choice and delta                                                                                                                                                                                    |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GGX microfacet reflection       | [Walter et al. 2007][W07], visible-normal sampling [Heitz 2018][H18]                                                          | Integrate the rough specular lobe with stochastic directions instead of the adapter's stock mirror ray plus roughness blur. Material roughness maps to GGX alpha as roughness squared                           |
| Spherical-cap VNDF sampling     | [Dupuy and Benyoub 2023][DB23]                                                                                                | Already implemented in the fork's sampler; simplify sampling without changing the intended VNDF                                                                                                                 |
| Bounded VNDF and matching PDF   | [Eto and Tokuyoshi 2023][ET23]                                                                                                | Already implemented. Restrict wasted below-surface samples with a corresponding PDF/weight correction; do not confuse this with an arbitrary mirror bias                                                        |
| Per-pixel temporal samples      | Four-dimensional low-discrepancy sequence with per-dimension hash rotations, implemented locally                              | Local sampling choice. Primary samples are not STBN; compare [Wolfe et al. 2022][BN22] rather than claiming their noise properties already apply                                                                |
| Screen-space traversal          | General background: [McGuire and Mara 2014][M14]; hierarchical traversal reference: [AMD SSSR][ASSR]                          | Our implementation projects a ray, marches depth or traverses a min-depth hierarchy, and refines a crossing. It is not claimed to be McGuire–Mara's exact DDA implementation                                    |
| Hierarchical min depth          | [ASSR] implementation guidance                                                                                                | Seven levels, finite traversal budget, full-resolution final hit checks. Tight-footprint reduction is opt-in; odd dimensions must cover leftover source texels                                                  |
| Front/back depth thickness      | Screen-space depth-interval reasoning; compare [M14]. Exact dual-layer implementation is local                                | Separate nearest back-face depth supplies additional hit acceptance inside a solid. It remains a screen-space approximation; back faces can belong to another overlapping object                                |
| Binary refinement               | Local crossing refinement using a bracketed interval                                                                          | Eight refinement iterations. Improves crossing localization but cannot restore hidden/off-screen geometry                                                                                                       |
| Ray clipping and march budgets  | Local implementation optimization                                                                                             | Precompute screen exit; different primary/secondary budgets. An exhausted budget is a miss, so speed changes can change visibility                                                                              |
| Hit specular redirection        | Microfacet reflection theory [W07], with the fork's material parameters                                                       | Re-evaluate hit specular for the reflected direction rather than treating view-dependent scene color as direction-independent radiance. The explicit secondary-ray approximation has its own budget             |
| Secondary roughness cutoff      | Local performance heuristic                                                                                                   | Rough hits can use prefiltered environment instead of tracing a second bounce. This is an approximation, not a theoretical guarantee                                                                            |
| Hidden-surface silhouette fetch | Local correction described in [SSR improvements](history/SSR_IMPROVEMENTS.md) and [temporal history](history/SSR_TEMPORAL.md) | Search compatible interior pixels to avoid sampling anti-aliased silhouette/background color for an accepted hidden-side hit                                                                                    |
| Environment on misses           | Existing environment/PMREM source along reflection directions; optional CDF/MIS helper                                        | Default `three-new` supplies the scene environment. Optional importance-sampled environment support exists but is not configured by this adapter                                                                |
| Optional environment MIS        | [Veach and Guibas 1995][VG95]; helper credits [three-gpu-pathtracer][GPT]                                                     | CDF construction and estimator adapted in `ImportanceSampledEnvironment`. Keep conditional activation clear; do not attribute default-pipeline gains to an inactive MIS option                                  |
| Radiance injection              | Local pipeline/material integration                                                                                           | Reflection radiance enters material lighting, including transparent-flagged surfaces, instead of simply adding stock SSR RGB afterward                                                                          |
| No artistic primary-ray fade    | Local fidelity choice                                                                                                         | Mirror bias zero, screen-edge fade zero, effectively disabled SSR luminance cap; `maxDistance` serves as a ray budget. These remove some deliberate biases but do not make the complete reconstruction unbiased |
| Optional radiance mips          | Local footprint heuristics, discussed in [hierarchical research](history/HIERARCHICAL.md)                                     | Only selected experiments prefilter primary hit radiance; preserve mirror/near-hit and secondary-bounce detail. This can blur and mix surfaces, so it requires quality measurements                             |

Screen-space tracing and the reflection estimator are different algorithms. A theoretical justification for GGX sampling does not justify every traversal acceptance test, radiance approximation, or reconstruction heuristic.

### Dedicated reflection filter

The active filter belongs to `NewSSRNode`, rather than the fork's generic specular denoising chain.

| Algorithm                                     | Source / relationship                                                                        | Choice and delta                                                                                                                                                            |
| --------------------------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Spatial ratio resolve                         | [Stachowiak 2015][SS15]                                                                      | Combine weighted radiance numerators/denominators before division; eight neighbor taps with local geometric compatibility. Finite-sample ratio reconstruction can be biased |
| Lobe-dependent footprint                      | GGX roughness and specular reconstruction background [NRD]                                   | Radius grows with roughness squared and is capped; mirrors keep their own ray. Our particular radius formula is a local heuristic                                           |
| Surface vs virtual reprojection               | Reflection parallax guidance [ADNS], specular reconstruction [NRD]                           | Compare both candidates with neighborhood statistics; virtual-point motion is computed between unjittered cameras and added to pixel UV                                     |
| History geometry validation                   | [ADNS] and [NRD] as reference designs                                                        | Surface path checks normals and distance; baseline virtual path checks normals. Validity is incomplete for complicated curved/dynamic reflections                           |
| YCoCg clipping                                | Temporal reconstruction background [Y20], [NRD]                                              | Componentwise clamp of history to local mean ± gamma·sigma. This is not TRAA's RGB clip-to-center operation                                                                 |
| Roughness-dependent history                   | Sample-count accumulation [ADNS]; parameters selected locally                                | History cap 4 for mirrors, up to 32 for rough surfaces. Those numbers are empirical choices, not paper-prescribed constants                                                 |
| Reflected-object motion rejection             | Local hit-motion residual correction; [NRD] provides the broader confidence/anti-lag context | Compare hit motion with camera-only motion, dilate the response, and tighten clipping/shorten history for dynamic hits. Misses can evade this signal                        |
| Upsampling                                    | Joint edge-aware reconstruction principle; actual code is local                              | Four bilinear taps weighted by depth-plane and normal agreement, with nearest fallback for thin features; identity at full resolution                                       |
| Per-tap history reconstruction (experimental) | Edge-history reconstruction in [ADNS]                                                        | Validate 2x2 taps before mixing; normalize RGB by accepted coverage. Coverage-weighted history count is our own confidence heuristic                                        |
| Gaussian clipping statistics (experimental)   | 9x9 Gaussian temporal statistics in [ADNS]                                                   | Sigma two pixels in YCoCg; adds to validated history. Wider statistics may preserve useful history but also allow lag across real changes                                   |

[NRD]'s same-seed lighting-gradient confidence and curvature-aware specular tracking are **not implemented by these experiments**. Adding longer history without valid reflected-feature alignment risks ghosts. Final TRAA supplies antialiasing and additional stabilization; it should not carry the whole reflection-denoising workload.

## SSGI: visibility-bitmask indirect diffuse lighting

The direct ancestry is [Screen Space Indirect Lighting with Visibility Bitmask, Therrien, Levesque and Gilet, journal 2022 / arXiv 2023][VB23] and the authors' [implementation explanation][VBC] / [SSRT3 source][SSRT]. The method builds on horizon-based sampling and [GTAO][GTAO], but replaces a continuous blocked-horizon range with individually occupied angular sectors.

| Algorithm                              | Source / relation                                                                                                | `three-new` choice and delta                                                                                                                                                                                                            |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hemisphere slices and finite thickness | [VB23], [VBC]                                                                                                    | Inherited bitmask method: sample both directions of each slice, use front/back angular bounds, and track 32 sectors. Thickness and finite radius remain approximations                                                                  |
| Visibility and first claimed sectors   | [VB23], [VBC]                                                                                                    | Bitwise accumulation prevents repeated samples from claiming already occupied sectors. `three-new` maintains separate lit and occluded masks because its GI gap correction differs from AO                                              |
| Sample distribution and jitter         | [GTAO] temporal rotations/spatial offsets, plus local sampling jitter                                            | Slice and step counts control quality/cost; temporal noise requires reconstruction. These particular sequences are not proof of optimal sampling                                                                                        |
| Solid-angle Jacobian                   | Spherical irradiance integration; local derivation in [GI estimator follow-up](history/GI-ESTIMATOR-FOLLOWUP.md) | Equal slice-angle sectors are not equal solid angles. New weighting approximates the Jacobian at the sample direction as `2·sqrt(1-(omega·view)^2)`; factor two preserves the established gain scale                                    |
| Receiver cosine                        | Diffuse irradiance integral                                                                                      | Multiply by `max(0,N·omega)`; preserve directional weighting rather than compensate missing energy with a global brightness multiplier                                                                                                  |
| Emitter-facing treatment               | Radiance transport plus projected angular coverage; local correction                                             | Read outgoing sample radiance and test emitter orientation. Avoid multiplying a second source cosine into radiance when its foreshortening is already represented by occupied sectors; backface-lighting behavior is still configurable |
| Depth/position agreement               | Texture sampling and inverse projection consistency; local correction                                            | Snap sampled UV to the depth texel center before rebuilding position. Removes slope-dependent mismatches on oblique surfaces                                                                                                            |
| Tangent-relative horizon               | Hemisphere geometry; local correction                                                                            | Compute elevation relative to the receiver's slice tangent/normal rather than assuming snapped samples remain exactly in the original view slice                                                                                        |
| Sector-center coverage                 | Discrete angular quadrature; local correction                                                                    | Round both endpoints. Stock floor-start/ceil-width can claim a sector for a nearly zero-width tangent sample and darken a flat surface                                                                                                  |
| GI gap filling                         | Local heightfield/continuity heuristic                                                                           | Light gaps between adjacent samples judged to lie on one tangent plane; skip away-facing fillers. Do not bridge depth discontinuities. Does not alter the AO occupancy mask                                                             |
| Previous-frame radiance feedback       | Local pipeline design                                                                                            | Reproject anti-aliased history into one RG11B10 source before many gathers, reducing repeated fetch work; feedback remains approximate for motion/visibility and indirect bounces                                                       |
| Radiance prefiltering                  | Optional local footprint approximation                                                                           | `ssgi-radiance-mips` prefilters distant radiance only; geometry stays full resolution. Color mips do not implement a new hierarchical GI estimator                                                                                      |
| Loop and expression optimization       | Local TSL code generation                                                                                        | Hoist initial step and emit slice/step/side loops with shared horizon stages. Preserve sampling order; smaller shaders alone do not establish runtime improvement                                                                       |
| HDR cap and distance fade              | Existing artistic/stability controls                                                                             | GI luminance is capped at 7; scene-specific distance fades may apply. These choices introduce bias and must be included in an upstream estimator discussion                                                                             |
| Material-lighting composition          | Local adapter integration                                                                                        | Inject AO and reconstructed GI with `builtinGIContext`. Stock adapter post-composites `color*AO + diffuse*GI`. Treat material response and estimator changes separately                                                                 |

The irradiance measure behind the weighting correction is

```text
E = integral L(omega) max(0, N dot omega) dOmega
  = integral L(alpha, phi) max(0, N dot omega) |sin alpha| dAlpha dPhi
```

The implemented sample-direction Jacobian is an approximation to sector integration. [GI estimator follow-up](history/GI-ESTIMATOR-FOLLOWUP.md) compares it with explicit per-sector weighting and analytic emitter controls. Its favorable reference score does not prove it is a more exact integrator; approximation errors can cancel.

## AO: shared visibility, separate reconstruction and evaluation

| Algorithm                  | Source / relation                                                       | Choice and delta                                                                                                                                                           |
| -------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bitmask ambient visibility | [VB23], [VBC]                                                           | Count occupied sectors, average slices, return one minus occupancy; then apply AO intensity exponent. This does not implement every analytic cosine-weighted GTAO integral |
| Finite-thickness occluders | [VB23]                                                                  | Unlike an opaque horizon that blocks everything below it, angular bit intervals let light/visibility pass behind thin surfaces                                             |
| Flat-surface corrections   | Same local depth snapping, tangent horizon, and sector rounding as SSGI | Intended to prevent flat geometry from self-occluding. Validate against flat/oblique controls before broad beauty comparisons                                              |
| Independent AO output      | Local MRT implementation                                                | AO and GI share geometry work but write separate signals; GI sector-gap filling leaves AO mask unchanged                                                                   |
| AO temporal reconstruction | Fork generic reprojection/recurrent filter                              | `three-new` separately reconstructs AO and GI; alpha is configured as `none`, so no reflection hit distance is inferred from these signals                                 |
| AO interpretation          | [GTAO] distinguishes visibility/occlusion from full illumination        | AO is an approximation to indirect visibility, not a substitute for missing irradiance. Keep AO-pass reference error separate from beauty error                            |

AO changes can improve flat-surface correctness while a coupled GI estimator temporarily becomes darker. That is not a reason to retain incorrect occlusion. Evaluate visibility and irradiance separately; [THREE-NEW.md](THREE-NEW.md) and the GI investigation logs describe those interactions.

## Shared AO/GI temporal and spatial reconstruction

| Algorithm                                  | Source / relation                                                   | Actual pipeline choice                                                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Previous geometry storage                  | Fork `PreviousFrameGeometry` source                                 | Share the previous depth/normal capture between AO and GI histories                                                                       |
| Motion reprojection and per-tap confidence | Fork `TemporalReprojectNode`; [P], [T], [L] implementation ancestry | Use diffuse-mode reprojection for these signals, validate geometry, reconstruct supported history, and track sample count                 |
| HDR neighborhood validation                | Fork source, [K14] / [Y20] background                               | YCoCg variance clipping with inverse-luminance compression. This is different from the dedicated SSR filter and final TRAA                |
| Recurrent edge-aware spatial filtering     | Fork `RecurrentDenoiseNode`; helpers explicitly credit REBLUR/[NRD] | Eight-tap Vogel disk with depth/normal/luminance edge stopping and recurrent history feedback                                             |
| Hit-distance/lobe helpers                  | REBLUR/[NRD] ancestry in the fork                                   | Present for specular mode, but AO/GI runs diffuse mode with `alphaSource='none'`; do not claim these inactive paths explain AO/GI results |
| Variance-guided reconstruction context     | [Schied et al. 2017, SVGF][SVGF]                                    | Useful theoretical comparison, not a claim that our recurrent filter implements SVGF's hierarchical wavelet algorithm                     |

The spatially filtered result becomes the next temporal history via `setHistoryTexture(denoised)`. This feedback arrangement has quality and bias implications. Preserve alpha semantics, normal encoding, resolution mapping, and pass ordering when changing the filters.

Reduced-resolution SSGI with bilateral reconstruction is separate ongoing work ([issue #107](https://github.com/bhouston/three-fidelity/issues/107)); it is not part of this base revision. Add its selected algorithm, primary source, footprint, normal/depth guidance, and quality evidence here when it lands.

## Preparing an upstream three.js PR

For each candidate, record a small, reviewable package of evidence:

1. **Source and scope:** paper/implementation link, exact equation or algorithm stage, licenses for adapted code, and which upstream node changes.
2. **Before/after mechanism:** concrete failure, changed estimator/validation step, and assumptions. Label local heuristics and parameter choices explicitly.
3. **Isolated controls:** flat and oblique surfaces for AO, analytic visible emitters for GI, roughness sweeps for SSR, checker/disocclusion sequences for TRAA.
4. **General-content evidence:** matched camera/object paths, moving and settled captures, PSNR plus brightness bias, noise/ghosting/detail measures, and repeated baseline runs.
5. **Cost and integration:** generated WGSL, compile/startup cost, GPU timings on an idle device, resource ownership, resize, camera cuts, and supported depth conventions.

Good candidates for separate proposals include depth-texel reconstruction consistency, sector-center rounding, tangent-relative horizons, and shader expression/loop reuse. Solid-angle weighting needs an estimator derivation and energy controls. GI gap filling, silhouette searches, roughness cutoffs, progressive averaging, and temporal clipping need broader bias/ghosting evidence before being promoted as universal improvements.

The new validated-history and Gaussian profiles are experimental. A paper citation justifies investigating them; it does not make their local adaptations production-ready. The temporal research document records the protocol and results.
